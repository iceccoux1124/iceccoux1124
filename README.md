## 我的開發方式

我不會直接從畫面或錯誤訊息開始亂改程式。

通常會先確認：

1. 問題發生在哪一層是否有報錯
2. 開始排查資料從哪裡進入系統
3. 哪個元件應該負責狀態
4. 修改是否會影響其他流程
5. 是否存在更小且可驗證的修正範圍
6. 如何避免同類問題再次出現

我重視的不只是「修好這次的 Bug」，而是理解問題為什麼發生，以及系統責任是否放在正確的位置。
